# ShellDeck 落地实现方案（Electron）

状态：v0.1.0 第一版已实现（终端、SFTP、工作区、Excel、托盘、更新校验与打包链路）。分发改为绿色文件夹：顶层入口 `ShellDeck.exe` + `runtime` 依赖目录，全部直连、关闭到托盘、明文 SQLite（方案 A）；更新采用 GitHub 主源、签名归一化清单、自定义/AGW 源和本地导入兜底。

## 1. 目标

在 ShellDeck 工作区做一个 Windows 专用、免登录、绿色文件夹分发的桌面 SSH 工具，基本复刻现有 Web SSH 工作区的能力：

- 左侧服务器清单、标签快速筛选、密码查看/复制。
- 原生 SSH 终端、SFTP 文件管理，全部直接连接目标服务器。
- 1/2/4/6/9 格工作区、每页按当前布局容量分页、拖动换位、放大、关闭、自动/手动文字缩放。
- 同服务器同类型重复打开二次确认。
- 常用指令、`{{参数}}` 替换、脚本在当前交互 shell 执行。
- Excel 导入/导出。
- 文件上传/下载/文件夹、覆盖确认、root 模式、权限、编辑、重命名、删除。
- 上传速度、当前文件进度、总进度、预计剩余时间。
- 最大化、最小化、最小化到系统托盘、托盘恢复/退出、单实例。
- 免登录；数据明文 SQLite，放在顶层入口 exe 同目录的 `data`，方便备份和恢复。
- 自动更新：GitHub Releases 为主，支持自定义静态源、AGW 适配源和本地安装包；Ed25519 签名清单、SHA-256 校验、失败回滚。

Web 专属的登录、权限/角色、SSH 小工具配对、下载小工具和「经 NAS」路由不进入 PC 版。

## 2. 技术栈

| 层 | 选择 |
| --- | --- |
| 桌面壳 | Electron（构建时固定稳定版本） |
| 前端 | Vue 3 + Vite + xterm.js + `@xterm/addon-fit` + SheetJS |
| SSH/SFTP | `ssh2`（Node） |
| 数据库 | SQLite，`better-sqlite3` |
| 更新校验 | Node `crypto`（Ed25519、SHA-256） |
| 更新安装 | 独立 PowerShell helper，等待主进程退出后替换 runtime exe |
| 打包 | `electron-builder --win dir` + 入口启动器，Windows x64 文件夹 |
| 样式 | 复用现有 `SshWorkspace.vue`、`SshFileSession.vue`、`SshTerminal.vue` 的布局与 CSS，改造成桌面数据接口 |

选 Electron 的原因：现有 Web UI、xterm 和交互可以直接复用，`ssh2` 的原生 SSH/SFTP 能力成熟，托盘/窗口/打包链路简单。代价是体积和内存高于 Tauri，按当前需求接受。

## 4. 进程与数据流

- Main process：窗口、托盘、SQLite、SSH/SFTP 会话、文件系统、系统对话框、更新检查/下载/安装。
- Renderer：Vue UI + xterm.js，不直接访问 Node、文件系统或数据库。
- Preload：`contextBridge` 暴露白名单 API，开启 `contextIsolation`、关闭 `nodeIntegration`。
- 不使用本地 HTTP/WebSocket 服务，全部走 Electron IPC，减少端口和安全面。

IPC 约定：

```text
servers:list / servers:save / servers:delete
commands:list / commands:save
settings:get / settings:set
terminal:open / terminal:input / terminal:resize / terminal:close
sftp:connect / sftp:close / sftp:list / sftp:read / sftp:write
sftp:mkdir / sftp:rename / sftp:remove / sftp:chmod
sftp:upload / sftp:download / sftp:cancel
dialog:pickFiles / dialog:pickFolder
app:backupDb / app:restoreDb / app:openDataDir
updater:getState / updater:check / updater:download / updater:install
updater:listSources / updater:addSource / updater:removeSource / updater:importLocal
```

Event：

```text
terminal:data      {sessionId, data}
terminal:closed    {sessionId}
terminal:error     {sessionId, message}
transfer:progress  {sessionId, transferId, bytes, total, bytesPerSecond, eta}
transfer:done      {sessionId, transferId}
transfer:error     {sessionId, transferId, message}
updater:state      {status, version, progress, error, source}
```

## 5. SQLite 设计

数据库文件：`data/ssh.db`，WAL 模式，明文保存。

```sql
meta(key TEXT PRIMARY KEY, value TEXT)
servers(
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  host TEXT NOT NULL,
  port INTEGER NOT NULL DEFAULT 22,
  username TEXT NOT NULL,
  password TEXT NOT NULL,
  note TEXT,
  tags_json TEXT NOT NULL DEFAULT '[]',
  created_at TEXT,
  updated_at TEXT
)
commands(
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  kind TEXT NOT NULL,              -- command | script
  body TEXT NOT NULL,
  created_at TEXT,
  updated_at TEXT
)
settings(key TEXT PRIMARY KEY, value TEXT)
update_sources(
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL,              -- github | static | agw | local
  base_url TEXT NOT NULL,
  enabled INTEGER NOT NULL DEFAULT 1,
  priority INTEGER NOT NULL DEFAULT 100,
  created_at TEXT
)
host_keys(host TEXT, port INTEGER, key_type TEXT, fingerprint TEXT, PRIMARY KEY(host, port, key_type))
```

- 服务器和指令均不限数量，支持快速搜索；标签、参数替换等规则沿用 Web。
- 密码/脚本明文保存，这是用户明确要求；界面提供“数据目录”和“备份数据库”入口。
- 备份使用 SQLite checkpoint + 文件复制，生成 `backups/ssh-YYYYMMDD-HHmmss.db`。
- 不保存终端 buffer、上传队列或登录会话；重启只恢复服务器、指令、窗口状态和布局偏好。
- 更新源配置入库；自动检查开关、上次检查时间等放 `settings`。

## 6. 连接方式

PC 版全部直连，不实现「经 NAS」跳板：

- 终端和 SFTP 都由桌面端直接连接服务器地址。
- 不做全局连接方式切换，也不再有强制 NAS 勾选。
- 网络不可达、认证失败、超时在对应会话内提示。

## 7. 终端实现

- 每个终端豆腐块对应一个 `ssh2` shell 会话，PTY 类型 `xterm-256color`。
- `terminal:data` 事件把远端数据推给 xterm；输入、resize 走 IPC。
- 支持多会话并发；隐藏页会话保持连接，翻页不重连。
- xterm scrollback 默认 3000 行，避免 9 会话无限增长。
- 复制/粘贴、Ctrl+C/D/L、Tab、Esc、上下历史与现有 Web 一致。
- `sudo -i` 快速切 root：发送命令，检测密码提示后自动填入服务器密码；错误可中断。
- 常用指令：命令直接在当前 shell 执行；脚本按当前交互 shell 发送，保留当前目录、环境变量和 stdin；`{{参数}}` 在发送前替换。
- 支持重连、关闭；窗口/页面隐藏不主动断开。
- 连接失败、认证失败、超时和断线在对应豆腐块内提示。

## 8. 文件实现

- 每个文件豆腐块独立 SFTP 会话。
- 列表、进入目录、面包屑、路径跳转、刷新。
- 上传文件/文件夹，保留目录层级；空文件夹也创建。
- 上传前检查目标目录同名文件，弹「跳过 / 覆盖 / 取消」；嵌套目录冲突仍需单独确认。
- 上传使用流式分块，回调计算：
  - 当前文件百分比
  - 总进度
  - 瞬时/滑动平均速度（B/s、KB/s、MB/s）
  - ETA
- 多文件/多文件会话可并行，但每个会话的队列有上限；不使用整文件内存缓冲。
- 下载流式保存，显示进度和速度。
- 文本编辑上限 2 MB；二进制文件拒绝编辑但可下载/删除。
- 新建文件夹、重命名、删除二次确认。
- 权限修改支持 644/755/600/700 和三位八进制；目录可递归。
- root 模式：非 root 用原生 SFTP；root 模式按 Web 现有方案，通过 SSH exec 执行逐项 `sudo`，路径 Base64，密码只发一次；列表、读取、写入、删除、chmod 都走 sudo。
- 仅本机直连 root 模式；由本机 SSH 会话执行 sudo。

## 9. 工作区 UI

- 复刻 Web SSH 工作区的布局：左侧服务器栏、当前服务器栏、布局工具栏、九宫格；不保留连接方式切换栏。
- 无会话时显示一个居中的「打开终端 / 打开文件」。
- 有会话时剩余空位显示「＋ 新建会话」，点击选择终端/文件。
- 右键左侧服务器弹出终端/文件菜单；单击只切换当前服务器。
- 布局 1/2/4/6/9；每页会话数等于当前布局容量，切换布局自动重新分页并校正页码；当前页满后新会话进入下一页；所有会话列表可跳转。
- 拖动标题栏换位、放大、关闭。
- 同服务器同类型重复打开二次确认。
- 自动按布局缩放文字，也允许手动比例；隐藏页和布局外会话保持挂载，不重连。
- 空状态、暗色终端、文件表格、标签、密码查看/复制沿用现有视觉。

## 10. 窗口与托盘

- 原生窗口边框，支持最大化、最小化、还原。
- 关闭按钮默认最小化到系统托盘；托盘右键菜单「打开主窗口 / 打开数据目录 / 检查更新 / 退出」；托盘双击恢复；只有托盘菜单「退出」才结束进程。
- 单实例锁：第二次启动恢复并激活已有窗口，不强制最大化、不改变窗口大小。
- 保存并恢复窗口位置和大小；启动时不恢复最大化状态。
- Windows 10/11 x64；高 DPI 适配。
- 退出时：有上传/命令运行时提示确认，避免误关；托盘退出也走同一确认。

## 11. Excel、标签和密码

- 服务器字段：名称、主机、端口、账号、密码、备注、标签。
- 标签筛选、搜索、标签编辑与 Web 一致。
- Excel 导入导出使用 SheetJS：ID、名称、主机、端口、账号、密码、备注、标签；导出当前筛选结果。
- 密码在列表中不显示；当前服务器栏查看/复制；导入/导出明文密码，提示妥善保管。

## 12. 打包与绿色运行

- `electron-builder --win dir` 生成 Windows x64 运行目录；`scripts/package-folder.cjs` 组装 `release/ShellDeck/`：顶层 `ShellDeck.exe` 为入口启动器，Electron 依赖全部放进 `runtime`。
- 入口启动器把 `runtime\ShellDeckRuntime.exe` 的工作目录设为 `runtime`，并设置 `SHELLDECK_DATA_DIR` 为顶层 `data`。
- `better-sqlite3` 是 N-API 预编译包，配置 `asarUnpack` 确保打包后可加载；不需要本机 VS 编译。
- 数据目录：开发用仓库根目录 `data/ssh.db`；打包后固定为顶层 `data/ssh.db`。目录不可写时明确报错，不写 AppData。
- 文件夹版没有自解压，启动不再等待解压；本机实测首开约 1 秒，二次启动约 0.2 秒且不改变窗口大小。
- 文件夹版当前不执行应用内替换；更新方式是退出后替换 `runtime`（入口有变化时替换整个文件夹），保留顶层 `data`。
- `update-helper.ps1` 的退出后替换/回滚逻辑保留在运行时资源中，供后续适配文件夹包更新；当前通过 `folderMode` 隐藏安装入口。
- 入口启动器依赖 Windows 自带的 .NET Framework 4.x；资源包含托盘图标，不依赖 Node/Maven/浏览器安装。

## 13. 自动更新

### 13.1 发布拓扑

- 本地 Git/Gitea 是开发主仓；确认版本后构建并发布到 GitHub Releases。
- GitHub 仓库公开；更新检查不依赖 `api.github.com`，直接使用 Release 资产静态地址，避免 API 限流和 403。
- 不在客户端嵌入 GitHub Token；GitHub 不可达时走自定义源、AGW 源或本地导入。
- 每次 Release 固定上传三个资产：
  - `ShellDeck-<version>-win-x64.zip`（建议打包 runtime 目录内容）
  - `release.json`
  - `release.json.sig`

GitHub 主源地址形如：

```text
https://github.com/<owner>/<repo>/releases/latest/download/release.json
https://github.com/<owner>/<repo>/releases/latest/download/release.json.sig
https://github.com/<owner>/<repo>/releases/latest/download/ShellDeck-0.2.0-win-x64.zip
```

### 13.2 归一化清单协议

所有更新源最终都转换成同一份静态清单，客户端只理解这一种格式：

```json
{
  "schemaVersion": 1,
  "appId": "com.shelldeck.desktop",
  "channel": "stable",
  "version": "0.1.0",
  "publishedAt": "2026-11-18T00:00:00Z",
  "minSupportedVersion": "0.0.1",
  "notes": "更新说明",
  "assets": {
    "win-x64": {
      "url": "https://example.com/ShellDeck-0.1.0-win-x64.zip",
      "size": 123456789,
      "sha256": "小写十六进制摘要"
    }
  }
}
```

- `release.json.sig` 是 detached Ed25519 签名（Base64），签名对象是 `release.json` 的原始字节，不是解析后的 JSON。
- 公钥内置于应用；支持按 `keyId` 预留轮换，首版内置一把发布公钥。
- 远程源和应用内本地导入都必须验签；签名不通过直接拒绝。
- 版本必须大于当前版本，且不低于 `minSupportedVersion`；不做降级。
- 下载后校验文件大小和 SHA-256，校验通过才允许启动 helper。

### 13.3 更新源与适配

- `github`：内置主源，直接拼 `releases/latest/download/` 静态地址。
- `static`：用户添加的 HTTPS 根地址，约定根目录下提供 `release.json`、`release.json.sig` 和清单中的资产。
- `agw`：主进程内的适配器读取 AGW 的索引/响应，把版本、说明、下载地址映射成归一化清单；不把 AGW 的字段格式硬编码进 UI，也不要求 AGW 模拟 GitHub API。
- `local`：用户选择本地目录或安装包；仍要求清单和签名，适合离线恢复。
- 源按 `priority` 顺序尝试；某个源 403/429/5xx/超时后进入指数退避（1h、6h、24h 封顶），并立即尝试下一个源。
- 自动检查默认每 24h 一次，启动后加随机抖动；支持手动「检查更新」。
- 缓存上次成功清单和已验证安装包；只缓存元数据不能直接安装，安装包必须重新校验。
- GitHub 被阻断时：切换到自定义静态源/AGW 源；提供「打开 GitHub Release 页面」浏览器兜底；仍不可用则本地导入。

### 13.4 下载与安装

当前文件夹版只做版本检查，应用内不执行替换；以下 helper 流程保留，供后续文件夹包更新适配。

1. 拉取清单和签名，验签、校验 `appId`/平台/版本。
2. 下载资产到 `data/updates/<version>/ShellDeckRuntime.exe.part`，流式计算 SHA-256，完成后改名为 `ShellDeckRuntime.exe`。
3. 用户点击「重启并安装」（默认提示重启，不静默重启）；退出前确认没有运行中的上传/命令。
4. 主进程启动 `update-helper.ps1`，传入当前 `runtime\ShellDeckRuntime.exe`、待安装 exe、备份路径、当前 PID。
5. helper 等待进程退出，将当前 runtime exe 备份为 `ShellDeck.previous.exe`，用新 exe 覆盖原文件，再启动新版本；顶层入口启动器不变。
6. 替换或启动失败时，helper 用 `ShellDeck.previous.exe` 回滚并重新启动；`data/` 全程不触碰。
7. 新版本启动后清理旧的 `.part`/临时文件；失败信息写入 `data/updates/update.log`，界面可查看。

### 13.5 更新安全

- 远程更新只接受 HTTPS；签名是强制项，SHA-256 是第二道校验。
- 清单包含 `appId`、`channel` 和平台资产，防止跨应用/跨架构误装。
- 不执行未验签的下载文件；不把更新源返回的任意命令交给 shell。
- helper 脚本随安装包只读资源提供，参数做路径和 PID 校验；路径含空格也必须正确引用。
- 更新失败不删除旧版本和业务数据；保留上一版本用于回滚。

## 14. 安全边界

- 免登录和明文密码是用户明确要求（方案 A）；数据库仅保存在本地，界面提示备份与 Windows 文件权限，不额外做启动密码或数据库加密。
- Electron：`contextIsolation: true`、`nodeIntegration: false`、禁用 remote、仅 preload 白名单 IPC。
- IPC 对路径、会话 ID、服务器 ID 做校验，renderer 不能执行任意 shell。
- 首次连接记录主机指纹；指纹变化时阻止并提示确认；可按服务器关闭严格校验（默认严格）。
- 不上传任何遥测或数据到外部服务；更新检查只请求版本清单和安装包。
